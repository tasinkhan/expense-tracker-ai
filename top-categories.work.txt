TESTING
-------
Approach: unit tests on the pure aggregation module with a fixed `now` (new Date(2026, 10, 22, 12) — local
mid-day so dates are timezone-safe). Covered:
- periodRange: all four periods; month/year edges (Jan 1 -> this month/this year = single day; last 30 days
  crossing into the previous year; leap-year Feb), PERIODS order.
- topCategories: empty input for every period; ranking order desc with zero-spend categories omitted;
  deterministic tie-break by CATEGORIES order; inclusive from/to boundaries for each period and exclusion of
  the day before / future dates; counts and averages rounded to cents (20.01/3 -> 6.67); float drift
  (0.1+0.2 -> 0.3, total 0.6) incl. tie after rounding; shares summing to 100 (thirds, single category = 100);
  shares/averages computed only from in-period expenses.

DESIGN DECISIONS
----------------
- Default period = "This month". The Dashboard already shows an all-time category breakdown, so the new page
  is most useful for the current, actionable period ("where is my money going right now"). Downside (early in
  the month there may be nothing yet) is handled by the "No spending in this period" state with a one-click
  "View all time" button.
- Periods end today and are inclusive, using exactly the same ranges as the FilterBar presets (This month =
  1st..today, Last 30 days = today-29..today, This year = Jan 1..today), so numbers match the Expenses page
  when the same preset is applied. All time is unbounded (includes any future-dated rows; the form forbids
  future dates anyway).
- Reuse: filterExpenses (with EMPTY_FILTERS + from/to) for the period filter and sumAmounts for every total
  so money is rounded to cents exactly like elsewhere. totalsByCategory was deliberately NOT used for ranking:
  it sorts on unrounded float sums, so exact ties like 0.1+0.2 vs 0.3 could rank inconsistently with the
  displayed (rounded) totals; the new code ranks on rounded totals with a stable CATEGORIES-order tie-break.
- share is returned unrounded (0-100) so it sums to 100 within float precision; the UI formats it with one
  decimal. average is rounded to cents in the lib.
- `now` is a parameter (defaulting to new Date()) on both periodRange and topCategories for testability.
  The page calls topCategories during render only after loading completes; the static prerender shows the
  skeleton, so no hydration mismatch from the date.
- Bar width represents share of the period total (requirement), unlike CategoryBreakdown which scales to the
  max; colors come from CATEGORY_STYLES (by category, never by rank) and the % is always shown as text.
- Kept it simple: no new shared components; the period toggle lives in the page.
