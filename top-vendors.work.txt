4. DATA MODEL CHANGE AND BACKWARD COMPATIBILITY
-----------------------------------------------
- `Expense.vendor?: string` is optional. The storage key ("expense-tracker:v1") and the shape of everything else are
  unchanged, so this needs no migration or version bump.
- Loading (parseStoredExpenses):
  * Entries without a vendor load unchanged.
  * A string vendor is trimmed.
  * A blank, null or non-string vendor is removed, and the expense itself is kept.
  * Existing shape checks (isExpense) are unchanged: malformed entries are still skipped and non-list data still throws.
- Saving:
  * The form always sends `vendor: trimmed || undefined`. Because updateExpense does { ...e, ...input }, clearing the
    field on edit removes a saved vendor.
  * JSON.stringify drops undefined keys, so an empty vendor is never saved as "".
- Older code reading newer data simply ignores the extra `vendor` key.
- CSV export (src/lib/csv.ts) is intentionally unchanged: the columns are still Date, Category, Description, Amount.
  FOLLOW-UP: decide whether to add a Vendor column. That changes an existing file format, so it may affect anyone
  re-importing the CSV.
- Other follow-ups:
  * Make the Expenses search (filterExpenses in src/lib/analytics.ts) match vendor too. I left analytics.ts alone to
    avoid conflicts with feature/top-categories.
  * Add vendor autocomplete (a datalist of known vendors) to the form.


5. TESTING
----------
Approach: the logic is in pure functions that take `now` as a parameter, tested with vitest in the node environment
and a fixed date: new Date(2026, 2, 15, 12:00 local). No DOM or React rendering tests.
Tests are co-located with the code (*.test.ts).

Covered:
- Normalisation: trimming and collapsing whitespace; null, undefined and blank values; case-insensitive key.
- Grouping: case and whitespace variants count as one vendor.
- Display name: most common spelling; ties go to the most recent spelling.
- Last purchase date; main category by spend, with ties resolved in CATEGORIES order.
- No-vendor handling: missing, "" and whitespace-only vendors stay out of the ranking; noVendor totals and share;
  noVendor is null when absent; a period with only vendor-less expenses.
- Ranking: total, then count, then name.
- Periods: exact inclusive ranges for each period; a leap-year February; last-30-days across a year boundary;
  filtering on the exact boundary days (the day before the window, first day, today, Jan 1, Dec 31 of last year);
  only expenses in the period are aggregated.
- Shares and rounding: totals rounded to cents (0.1 + 0.2 gives 0.3); shares to 1 decimal (33.3 x 3); no-vendor
  spending included in the share denominator.
- Empty input, and a period with no matching expenses.
- validateExpense: vendor is optional ("", whitespace); exactly 60 characters passes, also after trimming;
  61 characters gives "Keep it under 60 characters."
- Storage: null or "" input; legacy data loads deep-equal with no vendor key; vendor trimmed; blank, null or numeric
  vendor dropped but the expense kept; malformed entries skipped; non-list or invalid JSON throws.

6. DESIGN DECISIONS
-------------------
- Period bounds are inclusive YYYY-MM-DD string comparisons, like filterExpenses, using local dates (toISODate).
  * "This month" and "This year" are whole calendar ranges (e.g. Mar 1-31, Jan 1-Dec 31).
  * "Last 30 days" is today minus 29 days through today, which is 30 days including today.
  * The form blocks future dates, so the open upper bound of the calendar periods doesn't matter in practice.
- Share is measured against the whole period total, including expenses without a vendor, so vendor shares plus the
  no-vendor share add up to about 100%. Totals are rounded to cents like sumAmounts. Shares are rounded to 1 decimal
  and shown with toFixed(1).
- The No vendor row is always last and unranked, with muted styling and a grey bar. The ranked vendors always use the
  brand colour. Category colours appear only on the CategoryBadge, which follows the existing rule that colour follows
  category, never rank.
- The form trims the vendor and keeps the user's casing and inner spacing. Grouping collapses whitespace and ignores
  case, so the saved data stays exactly as the user typed it.
- The vendor input has maxLength=80, not 60, so a pasted long value shows the validation message instead of being cut
  off silently. This mirrors the description field (maxLength 140 with a 120 limit).
- The vendor field is labelled "Vendor (optional)" because it is the only optional field in the form.
- The "No vendors yet" state checks all expenses, not only the selected period. It replaces the period picker because
  switching periods can't help in that case.
- Navbar at phone width: three links plus the Add button would have overflowed at 375px. Changes:
  * links use px-2 below sm (px-3 from sm up)
  * the header gap is gap-2 below sm
  * the nav has min-w-0 overflow-x-auto as a safety net
  * the Add button is icon-only below sm, with aria-label="Add expense"; the separate "Add" span was removed
  At sm and wider, nothing changes visually.
- parseStoredExpenses was taken out of loadExpenses so storage can be tested without a DOM or localStorage mock.
